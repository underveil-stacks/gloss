# CLAUDE.md

Guidance for AI agents working in this repository. Everything needed to build and change Gloss is
in this repository; do not rely on documents outside it.

## What this is

Gloss is a read-only Markdown viewer for macOS (Apple silicon, current macOS only). It renders
with cmark-gfm into a web view. `README.md` says what it does; `docs/bundles.md` is the theme and
add-on contract; `docs/design/themes.md` explains the built-in themes.

## Commands

```sh
make build      # xcodegen + unsigned build
make core-test  # swift test for Packages/GlossCore
make test       # app tests in a real web view
make check      # both; run before every pull request
```

`Gloss.xcodeproj`, `App/Info.plist` and `QuickLook/Info.plist` are generated by XcodeGen from
`project.yml`. Edit `project.yml`, never the generated files. Run `xcodegen generate` (or any
`make` target) after adding or removing a source file, or it will not be compiled.

## How a page is made

1. `GlossCore.MarkdownRenderer` parses with cmark-gfm, passes the output through `HTMLSanitizer`,
   then adds heading ids, alerts and highlighted code by source position.
2. `PageModel` (`App/PageModel.swift`) chooses the theme and add-ons, builds the page with
   `HTMLPage.wrap`, and hands it to `PageStore`.
3. `PageStore` serves everything over the `gloss:` scheme: `gloss://doc/…` (the document root),
   `gloss://app/…` (three named files) and `gloss://bundle/<id>/…` (bundles the page uses).
4. When the file changes, the page is updated in place by `App/Resources/gloss.js`, which holds
   the reader's position by source line. A change of theme, appearance or policy reloads the page.

## Rules that are easy to break

- **The web page never gets a write path to disk, and no bridge to native code.** This holds even
  if editing is added later; editing would be a native pane, not the page.
- **Every page load goes through `PageStore`.** Do not load `file://` URLs, do not call
  `load(html:)` on the page directly, and do not add a second route to the disk.
- **The document is untrusted.** Do not weaken the content security policy in
  `GlossCore/HTMLPage.swift` to make a feature work. Raw HTML reaches the page only through
  `HTMLSanitizer`; anything inserted after sanitizing (heading ids, alerts, highlighted code) must
  be built by Gloss, never copied from the document unescaped.
- **Nothing loads from the network** unless the reader asks for it, per document.
- **Form answers live only in the page.** The app reads them (`gloss.forms`) when the reader
  exports; the page never hands them over by itself. A document may not use `password`, `file`
  or `hidden` inputs, buttons or `<form>`. Closing or quitting with answers not yet exported must
  keep asking first.
- **`GlossCore` has no UI dependency** and must keep building on Linux; CI tests it there. That is
  why the highlighter (JavaScriptCore) lives in the app and is passed in as a closure.
- **A change to trust or file serving needs a test in `AppTests/PageTrustTests.swift`** that loads
  a real page and asks it what happened. Check that the test fails when the protection is removed.
  Commit first: reverting a mutation with `git checkout` discards uncommitted work in that file.
- **The bundle contract is public.** `docs/bundles.md`, the page structure in `HTMLPage`, the
  tokens in `App/Resources/base.css` and the `gloss:render` event are what theme authors build
  against. Change them together, and only with a contract version bump if existing bundles break.
- **Built-in bundles cannot be shadowed.** `BundleLibrary` refuses a user bundle with a built-in's
  identifier. Keep it that way.
- **The app is not sandboxed and is signed with the hardened runtime.** The Quick Look extension
  is sandboxed, as extensions must be. CI and `make` build unsigned; only `scripts/release.sh`
  signs.
- **Releases are built by `scripts/release.sh`** on a developer's Mac, with a GA Xcode. CI never
  signs or publishes.

## Checking the running app

The app is scriptable (`App/Resources/Gloss.sdef`, `App/Scripting.swift`), and `skills/gloss` wraps
that in a command. Use it to confirm a change in the real app instead of guessing:

```sh
make build
export GLOSS_APP="$PWD/build/Build/Products/Debug/Gloss.app"
skills/gloss/scripts/gloss open README.md
skills/gloss/scripts/gloss outline README.md
skills/gloss/scripts/gloss info README.md
skills/gloss/scripts/gloss quit
```

- Wait for `loading` to be false before reading `page text`, `page html` or `outline`. The `gloss`
  command does this.
- **Check whether Gloss is already running before you script it** (`pgrep -x Gloss`). A script
  addressed to a build path reaches whichever copy is running, including the user's installed
  one, and `close` or `quit` would then close their windows. If a copy is running that you did
  not start, leave it alone. Launch your own with `open -n -a "$GLOSS_APP" <file>` and stop it by
  process id.
- Xcode registers each build with Launch Services, and macOS may then open the user's Markdown
  files in the build-folder copy (unsigned, blank Dock icon). The `make` targets and the release
  script run `scripts/unregister-builds.sh` to undo that; run it yourself after a bare
  `xcodebuild`.
- Debug and installed copies share settings and saved window state, because they share a bundle
  identifier. Close the documents you opened, and put back any setting you changed.
- Gloss reopens the documents that were open when it last quit. Refer to documents by name, and
  close what you opened before quitting.
- `count of windows` includes hidden windows. Count documents.
- Documents are read-only to scripts; settings (appearance, themes, zoom) may be set. Do not add
  scripting that writes, creates or deletes a document.
- The dictionary's Standard Suite is a trimmed copy with no `save`, `print`, `make`, `delete`,
  `duplicate` or `move`. Do not add them back: `save` raises a modal alert that blocks the script.
- `skills/gloss/SKILL.md` is also bundled in the app and returned by `agent guide`. When the
  scripting interface changes, update the dictionary, the skill and its `gloss` script together.
- Installing a bundle and the default-viewer prompt show modal alerts that a script cannot answer.
  Do not trigger them from a test.
- Checking menus through System Events needs Accessibility permission for the terminal.
